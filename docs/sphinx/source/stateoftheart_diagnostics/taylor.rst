Taylor Diagnostic
=================

Description
-----------

The **Taylor** diagnostic evaluates how well the spatial pattern of a model climatology matches a reference dataset
and summarises the result in a Taylor diagram (`Taylor, 2001 <https://doi.org/10.1029/2000JD900719>`_).

Each point of the diagram shows, at once, three statistics of a field with respect to its reference:

* the **pattern correlation**, as the angle from the horizontal axis,
* the **standard deviation** of the pattern, as the radial distance from the origin,
* the **centred root mean square difference** (CRMSD), as the distance from the reference point, drawn as dashed contours.

The three statistics are related by the law of cosines, ``CRMSD² = σ² + σ_ref² - 2 σ σ_ref R``, which is what makes
the geometric representation exact. The standard deviation and the CRMSD are normalised by the standard deviation of the reference,
so that the reference sits at distance 1 on the horizontal axis and variables with different units can be compared in a single diagram.
The better the model, the closer its point to the reference.

The diagnostic compares the annual climatology and, optionally, the four seasonal climatologies (DJF, MAM, JJA, SON) of each variable.
Statistics are weighted by the cell area, and computed only where both the dataset and the reference are defined.

Classes
-------

There is one class for the analysis and one for the plotting:

* **Taylor**: retrieves the data of a single dataset (with unit conversion, formulae, pressure level and region selection),
  computes its annual and seasonal climatologies and, given a reference ``Taylor`` instance whose climatology has already
  been computed, the statistics of the Taylor diagram.
  The statistics are saved as a NetCDF file and can be read back with the ``load()`` method.
  The reference is a ``Taylor`` instance as well, so that its climatology is computed once and shared by all the datasets.

* **PlotTaylor**: produces the Taylor diagrams from the statistics of one or more datasets and variables.

Two generic functions are also available, and can be used on any data:

* ``compute_taylor_statistics``: the weighted statistics of the Taylor diagram between two fields on the same grid,
  over any set of dimensions (e.g. space, or space and time).
* ``plot_taylor_diagram``: the graphics function, which only needs standard deviations and correlations.
  It follows the conventions of ``aqua.core.graphics``, where it is meant to be moved.

File structure
--------------

* The diagnostic is located in the ``aqua/diagnostics/taylor`` directory, which contains both the source code and the command line interface (CLI) script.
* A template configuration file is available at ``aqua/diagnostics/templates/collections/config-taylor.yaml``.
* The diagnostic is part of the ``atmosphere2d`` (against ERA5) and ``radiation_toa`` (against CERES) collections.
* Notebooks are available in the ``notebooks/diagnostics/taylor`` directory and contain examples of how to use the diagnostic.

Input variables and datasets
----------------------------

The diagnostic can be used with any 2D variable, or 3D variable on pressure levels by selecting a level.
Dataset and reference must be on the same grid: the diagnostic raises an error otherwise, and the ``regrid`` option should be used.
At least 12 months of data are required.

The diagnostic is designed to work with data from the Low Resolution Archive (LRA), generated by
the Data Reduction OPerator (DROP) of the AQUA project, which provides monthly data at a 1x1
degree resolution. Observational references are regridded to the same 1x1 degree grid.

Basic usage
-----------

The basic usage of this diagnostic is explained with a working example in the notebook.
The basic structure of the analysis is the following:

.. code-block:: python

    from aqua.diagnostics import Taylor, PlotTaylor

    reference = Taylor(catalog='obs', model='ECMWF', exp='era5', source='monthly', regrid='r100',
                       startdate='1990-01-01', enddate='2014-12-31')

    statistics = []
    for var in ['2t', 'msl', 'tcc']:
        reference.run(var=var)

        taylor = Taylor(catalog='climatedt-gen2', model='IFS-NEMO-5km', exp='baseline-hist', source='lra-r100-monthly',
                        startdate='1990-01-01', enddate='2014-12-31')
        taylor.run(var=var)
        taylor.compute_statistics(reference=reference, outputdir='./')
        statistics.append(taylor.statistics)

    plot = PlotTaylor(outputdir='./')
    plot.plot_taylor(statistics, period='annual', color_by='var', marker_by='dataset')

The ``run()`` method accepts the ``units``, ``long_name``, ``short_name``, ``plev`` and ``formula`` options,
and the ``Taylor`` class accepts a ``region`` from the centralised regions file.
The statistics are an ``xarray.Dataset`` with a ``period`` dimension and the following variables:
``std``, ``std_ref``, ``corr``, ``crmse``, ``bias``, ``rmse``, ``std_norm`` and ``crmse_norm``.

The points of the diagram are the combinations of dataset, variable and period.
The ``color_by`` and ``marker_by`` options of ``plot_taylor()`` select which of these (``'var'``, ``'dataset'``, ``'period'``)
the colors and markers distinguish. For example, a seasonal diagram of a variable for multiple models:

.. code-block:: python

    plot.plot_taylor(statistics_2t, period='seasonal', color_by='period', marker_by='dataset')

With a single variable and period, ``normalize=False`` produces the diagram in physical units.

To plot from the NetCDF files of a previous run, without retrieving any data:

.. code-block:: python

    reference = Taylor(catalog='obs', model='ECMWF', exp='era5', source='monthly')
    taylor = Taylor(catalog='climatedt-gen2', model='IFS-NEMO-5km', exp='baseline-hist', source='lra-r100-monthly',
                    startdate='1990-01-01', enddate='2014-12-31')
    taylor.load(var='2t', reference=reference, outputdir='./')

CLI usage
---------

The diagnostic can be run from the command line interface (CLI) by running the following command:

.. code-block:: bash

    cd $AQUA/aqua/diagnostics/taylor
    python cli_taylor.py --config <path_to_config_file>

The CLI accepts the arguments common to all the diagnostics (see :ref:`diagnostics-cli-arguments`).

For each variable, the climatology of the first reference is computed once and each dataset is compared with it.
The CLI produces, for each region:

* one annual Taylor diagram with all the variables, where colors distinguish the variables and markers the datasets,
* if ``seasons`` is enabled, one seasonal Taylor diagram per variable, where colors distinguish the seasons.

The ``plot_only`` option is supported (see :ref:`diagnostics-plot-only`).

Configuration file structure
----------------------------

The configuration file is a YAML file that contains the details on the dataset to analyse or use as reference, the output directory and the diagnostic settings.
Most of the settings are common to all the diagnostics (see :ref:`diagnostics-configuration-files`).
Multiple datasets are supported, while only the first reference is used.
Here we describe only the specific settings for the Taylor diagnostic.

* ``taylor``: a block (nested in the ``diagnostics`` block) containing options for the Taylor diagnostic.

    * ``run``: enable/disable the diagnostic.
    * ``diagnostic_name``: name of the diagnostic, used in the filenames. ``taylor`` by default, but it can be changed when the
      diagnostic is part of a collection (e.g. ``atmosphere2d``).
    * ``seasons``: if ``true``, compute the seasonal statistics and produce a seasonal diagram per variable. Default is ``true``.
    * ``variables``: list of variables to analyse. Each entry can also be a dictionary with a ``name`` and any of the parameters below,
      e.g. to analyse the same variable at different pressure levels.
    * ``formulae``: list of formulae to analyse. A ``short_name`` is recommended, as it is used in the filenames and in the plots.
    * ``params``: parameters of the variables, with a ``default`` block and one block per variable. Available options are
      ``units``, ``long_name``, ``short_name``, ``plev`` and ``regions`` (a list of regions from the centralised regions file, ``null`` for the whole domain).
    * ``plot_params``: plot options, ``std_max`` (the maximum of the normalised standard deviation axis, ``null`` for automatic)
      and ``annotate`` (write the variable name next to each point).

.. code-block:: yaml

    diagnostics:
      taylor:
        run: true
        diagnostic_name: 'atmosphere2d'
        seasons: true
        variables: ['2t', 'msl', 'tcc', 'tprate']
        formulae: ['(10u^2+10v^2)^0.5']
        params:
          default:
            regions: [null]
          tprate:
            units: 'mm/day'
          (10u^2+10v^2)^0.5:
            short_name: "10si"
            long_name: "Wind speed at 10m"
        plot_params:
          std_max: null
          annotate: false

Output
------

The diagnostic produces:

* one NetCDF file per dataset, variable and region, with the statistics of all the periods (``taylor_statistics``).
  The filename includes both the dataset and the reference, since the statistics depend on both.
* the Taylor diagrams described above (``taylor_diagram``), in the formats selected in the configuration file.

Observations
------------

The default reference datasets are:

* ERA5 reanalysis for atmospheric variables (``atmosphere2d`` collection)
* CERES EBAF for the radiation at the top of the atmosphere and the cloud radiative effects (``radiation_toa`` collection)

Custom reference datasets can be configured in the configuration file.
